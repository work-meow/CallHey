# CallHey

Видеозвонок по ссылке — до 8 участников, с демонстрацией экрана и чатом. Браузеры передают аудио, видео и сообщения напрямую через WebRTC (full mesh); Go-сервис хранит только состав комнаты и пересылает сигналы соединения через HTTP/SSE. Медиатрафик и переписка через сервер не идут.

## Возможности

- До 8 участников в комнате, вход по одной ссылке без регистрации.
- Демонстрация экрана — подменяет исходящий видеотрек, соединение не рвется.
- Чат поверх `RTCDataChannel`: сообщения идут P2P, сервер их не видит и не хранит.
- Живая статистика по каждому участнику: задержка, потери, битрейт, джиттер, разрешение, кодек и маршрут соединения.
- Выбор STUN-сервера с замером задержки прямо из браузера; переключение применяется без разрыва звонка.
- Подсветка говорящего, индикаторы выключенного микрофона и демонстрации экрана у собеседников.
- Личные настройки звука: выбор микрофона, камеры и устройства вывода, громкость своего микрофона с индикатором уровня, три режима обработки — без нее, стандартная и с изоляцией голоса.
- Своя громкость для каждого собеседника вплоть до полного мьюта. Настройка локальная: участник о ней не узнает.
- Правый клик по участнику открывает меню с его громкостью, мьютом для себя, закреплением, полноэкранным режимом и отдельным окном.
- Качество исходящего видео — от 360p до 1080p или автоматически; для демонстрации экрана отдельный выбор между четкостью и плавностью. Применяется на лету, без переподключения.
- Плитка участника разворачивается на весь экран (или по двойному клику), выносится в отдельное окно поверх других приложений и закрепляется на всю сцену; начатая демонстрация закрепляется сама.
- Горячие клавиши: `M` — микрофон, `V` — камера, `S` — экран, `C` — чат (работают и в русской раскладке).
- Работа без камеры: звонок собирается на одном микрофоне, чужое видео при этом принимается.

## Запуск

Требуются Go 1.24+ и Node.js 22+.

```powershell
cd backend
go run .
```

```powershell
cd frontend
npm ci
npm run dev
```

Откройте `http://localhost:3000`, создайте звонок и отправьте полученную ссылку остальным. Камера и микрофон работают на `localhost` или через HTTPS.

## Настройка

- `backend/ALLOWED_ORIGINS` — адреса frontend через запятую, например `https://callhey.example.ru`.
- `frontend/SIGNAL_URL` — публичный HTTPS-адрес signaling backend, например `https://api.callhey.example.ru`. Читается на сервере при рендере, поэтому меняется без пересборки — достаточно перезапустить контейнер.
- `frontend/TURN_*` — TURN-сервер для сетей, где прямой WebRTC заблокирован. Без него звонок не соберется за симметричным NAT.

Для развертывания соберите `backend/Dockerfile` и `frontend/Dockerfile`, выдайте обоим сервисам HTTPS и заполните переменные из `.env.example` в их каталогах. Сборка backend прогоняет `go test` — деплой упадет, если тесты красные.

## Как устроено

- Комната адресуется случайным `roomId` из ссылки; участник получает приватный `token` (для своих запросов) и публичный `id` (для адресации сигналов).
- Новый участник узнает состав комнаты в ответе на вход, а уже вошедшие получают `peer-joined` и сами шлют ему offer — встречные офферы разруливаются по schema perfect negotiation.
- Очередь событий на сервере удаляет сообщение только после успешной отправки, поэтому обрыв SSE не теряет offer или ICE-кандидат.
- Переподключение SSE вытесняет прошлый поток, а не получает отказ: иначе `EventSource` в браузере закрылся бы навсегда.
- Ушедший участник освобождает место через `sendBeacon`, а если тот не доехал — через TTL в 20 секунд после обрыва потока.
- Демонстрация экрана подменяет исходящий видеотрек через `replaceTrack`, без переговоров и разрыва соединения.
- Чат и состояние участников идут в `negotiated`-канале данных с общим id: обе стороны открывают его сами, лишних переговоров нет. Входящие сообщения приходят от другого клиента, поэтому проходят валидацию в `lib/wire.ts`.
- Кто говорит, определяется локально по громкости потока через один общий `AudioContext`.
- Микрофон идет к участникам через регулятор громкости (`lib/mic.ts`). Выходной трек создается один раз на звонок, поэтому смена микрофона на лету не требует переговоров: меняется только источник в начале цепочки. Все исходящие треки лежат в одном `MediaStream` — по его `msid` собеседник собирает звук с картинкой в одну плитку.
- Громкость собеседника и устройство вывода живут на `<video>` (`volume`, `setSinkId`), в сеть не уходят и другой стороне не видны.
- Качество видео задается через `setParameters` на отправителе и `applyConstraints` на треке (`lib/quality.ts`) — то есть на живом соединении, без переговоров. Ограничения ставятся после `connected`: до переговоров у отправителя еще нет `encodings`.
- Демонстрация экрана выставляет треку `contentHint` (`text` или `motion`) и `degradationPreference`. Это решает, чем кодек пожертвует при нехватке канала: разрешением или частотой кадров. Для текста верно первое, для видео — второе, одним «качеством» это не описывается.

## TURN

STUN хватает, только когда хотя бы одна сторона может принять входящее UDP-соединение. Мобильный интернет с CGNAT, корпоративные сети и симметричный NAT так не умеют: ICE молча висит в `checking`, и звонок не собирается. Приложение распознает это за 15 секунд и показывает причину вместо бесконечного «подключается».

Развертывание ретранслятора — `turn/docker-compose.yml`. В Dokploy это отдельный Compose-сервис; переменные берутся из `turn/.env.example`. После запуска пропишите в окружении frontend:

```
TURN_URL=turn:<публичный-ip>:3478,turn:<публичный-ip>:3478?transport=tcp
TURN_USERNAME=callhey
TURN_CREDENTIAL=<пароль из TURN_PASSWORD>
```

`TURN_URL` принимает несколько адресов через запятую. Второй — запасной путь по TCP для сетей, где UDP вырезан целиком; ICE берет его, только если UDP не прошел.

На фаерволе нужно открыть `3478/udp`, `3478/tcp` и диапазон `49160-49200/udp`. Проверить сервер можно на https://icetest.info — при верной настройке в списке появятся кандидаты типа `relay`.

Через TURN идет весь медиатрафик, поэтому в full mesh на 8 участников нагрузка на канал сервера растет кратно. Квоты в compose-файле это ограничивают.

## Ограничения

Full mesh: каждый участник шлет свое видео каждому. До 8 человек это работает на обычном канале, дальше нужен SFU.
